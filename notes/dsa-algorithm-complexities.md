# DSA algorithm complexities

Inventory: **63 Java files** under `src/DSA`, inspected recursively. Bounds describe the **implemented code**, not proposed optimizations or complexity comments. Source links are relative to this document. No source code was changed.

## Conventions

- `O` gives a worst-case upper bound unless explicitly qualified. Use `log(x+1)` where a size can be zero. Fixed-width Java arithmetic, comparisons, and array access cost `O(1)`; overflow, allocation limits, invalid inputs, and stack overflow can invalidate a result without improving its algorithmic bound.
- **Auxiliary space excludes input and returned output**, but includes recursion, temporary strings, sorting workspace, and traversal queues. For stateful structures, “state” is retained storage; per-call workspace is listed separately. Output is stated where nonconstant.
- **Hash qualification (`†`)**: the displayed time assumes expected constant-time hash lookup and amortized constant-time hash insertion, with bounded-cost keys. It is **not an unconditional worst-case guarantee**. A conservative collision/rehash upper bound is obtained by multiplying the marked time by `H+1`, where `H` is the maximum number of entries in any hash collection involved. This intentionally conservative bound also covers `IdentityHashMap` probing; it does not rely on JVM-specific treeification. String hashing/equality can additionally cost the key length, unless already counted or identifiers are treated as bounded.
- Heap offer and dynamic-array/deque append bounds use **amortized backing-array growth**. A single growth operation can additionally cost `O(H)` for a heap/array/deque containing `H` elements; removal/heap sift costs remain `O(log H)`. Thus a heap-insertion row marked “amortized” has a single-call worst-case bound including that linear growth. Whole-batch traversal/sort bounds already absorb growth.
- Object-array/list comparison sorting uses `O(n log n)` comparisons and up to `O(n)` auxiliary workspace. “In-place sort” of an object array does **not** imply `O(1)` auxiliary space. List-indexed algorithms assume random-access input lists unless noted.
- Tree notation: `n` nodes, `h` height, `w` maximum width. Graph notation: `V` vertices, `E` input edges (including duplicates if accepted). Other variables are defined locally. Main methods that only construct fixed examples and print results are covered by their algorithm rows, not counted as new implementations.

- Folder totals: root **16**, Agoda **3**, Amazon **15**, Apple **6**, Atlassian **2**, Google direct **16**, Google/Multithreading/PipelineManager **4**, closestGroup **1** = **63 Java files**.
- Every file appears in an algorithm table or an explicit support-file coverage note. - These are static code-analysis bounds, not benchmark measurements or assertions that all implementations solve their stated problem. Particularly conditional cases are the Babylon reachable-state count, sparse Aho–Corasick failure/output work, string-bearing priority search, arbitrary iterator/job callback costs, retained collection capacity, and concurrent failure termination.
- All links target the inspected Java files. No bounds are assigned to unimplemented optimizations mentioned only in comments (for example, PaintingFence segment trees or full-table wildcard DP).
